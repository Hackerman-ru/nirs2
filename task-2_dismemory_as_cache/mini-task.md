# Мини-задание по статье "Rethinking Software Runtimes for Disaggregated Memory"

### Выполнил Корняков Санан Арсланович

## Описание задачи

Авторы статьи ставят задачу уменьшить задержки и ненужные прогоны данных по сети в системах, использующих дезагрегированные хранилища. Современные решения, основывающиеся на виртуальных страницах памяти и page fault-ах, не удовлетворяют нынешним высоким требованиям из-за частого инвалидирования TLB и лишней постраничной записи малых изменений.

## Поставленные требования

Объявлены несколько требований к решению данной задачи:

- Прозрачность для приложений. То есть, приложения не должны замечать, что работают с дезагрегированным хранилищем, и не должны модифицировать код под его нужды
- Записывать обратно только изменённые кэш‑линии; высокий network goodput и низкая write amplification
- Аппаратные префетчеры не должны блокироваться page fault‑ами
- Заставить hardware следить за доступом к памяти. Железо уже это делает, надо только пару ручек добавить
- Ортогонализовать размер данных приложения и размер виртуальных страниц, чтобы data movement amplification не мешало использовать huge pages
- Отказоустойчивость. Всё-таки мы работаем с распределёнными системами

## Ключевые предположения

Выдвинуты следующие предположения:

- Скоро магическим образом во все сервера и компьютеры добавятся новые железки с поддержкой нужных функций (ага-ага)
- Задержки сети около 3 микросекунд, поэтому они не вносят большой вклад в общую задержку
- В реальном мире модифицируют 1-8 кэш-линий, или есть локализация изменений, что даёт выигрыши от маленького размера кэш-линий по сравнению с постраничным отслеживанием

## Компромиссы

- Нужна аппаратная поддержка для достижения наилучших результатов
- Из-за сбоев сети возможны таймауты когерентности и MCE; требуется обход через перевод части путей обратно на page fault-ы
- Ограничение видимости: FPGA не видит CMem — «дальние» данные должны жить в VFMem.
