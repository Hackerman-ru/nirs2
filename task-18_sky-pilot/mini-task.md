# Мини-задание по статье "SkyPilot: An Intercloud Broker for Sky Computing"

### Выполнил Корняков Санан Арсланович

## Описание статьи

Статья представляет концепцию **Sky Computing** и систему‑брокер **SkyPilot**, решающие проблему разнордности API от разных поставщиков и гравитации данных. Он автоматически размещает задачи в разных облаках, оптимизируя стоимость, производительность и доступность на основе требований пользователя.

## Слабые стороны и ограничения подхода Sky Pilot

### Ограниченная применимость для интерактивных нагрузок

Подход ориентирован на batch‑задачи, а для интерактивных, stateful или real‑time приложений (например, веб‑сервисов) он менее эффективен. Возникают проблемы с задержками, гарантиями QoS и управлением состоянием. Например, невозможно обеспечить размещение инстансов близко к пользователям или быстрое автомасштабирование.  

*Решение:* расширить функционал для поддержки edge‑вычислений, stateful‑сервисов и SLO/QoS‑политик (приоритетное размещение, резервирование ресурсов).

### Трудности отладки в мультиоблачной среде
Диагностика сбоев усложняется из‑за разнородных источников логов и метрик. Сложно определить, где возникла проблема (в облаке, сети, брокере или приложении). Например, задача падает в GCP из‑за таймаута при чтении данных из AWS S3, но пользователь видит лишь общую ошибку.  

*Решение:* внедрить единый слой логирования и трассировки (например, OpenTelemetry), предоставить API для доступа к логам/метрикам и разработать инструменты для диагностики мультиоблачных сбоев.

### Риски, связанные с передачей данных
Реальные затраты на передачу данных (egress fees, задержки) могут превысить ожидаемые из‑за неточных оценок размера данных, скачков цен или сетевых проблем. Например, перенос 1 ТБ данных может оказаться дороже из‑за внезапного повышения платы или низкой пропускной способности сети.  

*Решение:* улучшать точность оценок стоимости и размера передачи, интегрироваться с сервисами нулевого egress (например, Cloudflare R2) и позволять пользователям задавать бюджеты.
